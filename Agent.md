# Verified runtime notes

- On Apple Silicon, macOS swap uses `/private/var/vm` on the system data volume even when source, runtime, and output are on an external drive. `scripts/apple_preflight.py` reports this volume but does not enforce a fixed free-space threshold; the user explicitly removed that threshold. Place job files on the work volume and stop on actual disk-full or MPS out-of-memory errors.
- VOSR's DINOv2 encoder can load and run on MPS from a local checkout with its pretrained weights under `preset/ckpts/torch_cache/checkpoints`. The current upstream DINOv2 source uses `float | None` annotations that fail at import on the Mac's Python 3.9; adding `from __future__ import annotations` to `dinov2/layers/attention.py` and `dinov2/layers/block.py` made a 224-pixel MPS forward pass produce finite features. This validates the encoder only, not the complete VOSR pipeline.
- A VOSR 0.5B one-step 4x run completed on Apple M2/MPS at 6144×4096 in 407.59 seconds wall time, but the native-pixel review rejected it: skin gained coarse artificial texture, glazing gained parallel streaks, and background plant detail lost consistent focus. A 768-pixel-tile crop retry did not repair those defects. Treat this backend as an unaccepted experiment, not a verified Super-Resolution delivery path; the candidate and failure review are under `/Volumes/work/Ai/Super-Resolution-tests/2026-09-28-deep-focus-v2/vosr-rejected-6k/`.
- The official VOSR2 1.4B one-step model, Qwen-Image 2D VAE, and DINOv2-L ran on Apple M2/16 GiB using PyTorch MPS with CPU fallback disabled. A 512×512 source crop passed visual comparison against the failed 0.5B result. The 1536×1024 source produced one 6144×4096 PNG in 672.26 seconds of model processing; the preflight-to-file timestamp gap was 756 seconds. Native-pixel review passed three distinct faces, knit and linen, visible hands, greenhouse glazing, foliage, and source-consistent depth. The finalizer accepted the file-bound review. This validates this synthetic-scene route, not all photographic inputs or real identity restoration.
- Two earlier VOSR2 full-image attempts were stopped in Qwen VAE decode after severe swapping. For this 16 GiB MPS path, `del state_dict` immediately after weight loading and moving DiT/DINOv2 off MPS before decode were necessary; the completed run applied both. Preserve those lifecycle steps in `patches/vosr2-mps.patch`. MPS runs on the Apple GPU; no Apple Neural Engine use was verified.
- The patched VOSR2 MPS executor accepts one input image per run. A two-image folder was rejected before model loading; this prevents accidental CPU execution on a second image after the first run moves DiT/DINOv2 off MPS.
